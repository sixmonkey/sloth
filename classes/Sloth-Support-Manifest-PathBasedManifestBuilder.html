PathBasedManifestBuilder extends AbstractManifestBuilder
in package
  • Application

AbstractYes
PathBasedManifestBuilder.php : 40

Base class for manifest builders that discover files from app/ and theme/ directories.

Extends AbstractManifestBuilder with path-based discovery. Subclasses only need to implement directory() to specify which subdirectory to scan (e.g. 'Model', 'Taxonomy', 'Api').

What this adds

  • directory() — abstract method that subclasses must implement. Returns the subdirectory name relative to app/ and theme/.
  • directories() — returns [app/path(), theme/path()] based on directory().
  • requireFiles — defaults to true (manifest emits require_once statements).

Builder hierarchy

AbstractManifestBuilder (minimal — lifecycle only)
├── PathBasedManifestBuilder (this class — scans app/theme directories)
│   ├── ModelManifestBuilder
│   ├── TaxonomyManifestBuilder
│   ├── ModuleManifestBuilder
│   ├── ApiControllerManifestBuilder
│   ├── ProvidersManifestBuilder
│   └── IncludesManifestBuilder
└── VendorProviderManifestBuilder (vendor packages via ComposerFinder)

entries()

AbstractManifestBuilder.php : 291

Entry data to return from the manifest, consumed by Registrars.

protected entries(array<string, string> $map) : array<string, mixed>

Compute registration arguments here. This method runs once at build time and the result is cached in the manifest file via var_export(). Registrars read this data at runtime without recomputation.

The returned array is keyed by identifier (class name). Each value should contain all the information a Registrar needs to perform its WordPress registrations.

Example:

return [
    '\\App\\Model\\NewsModel' => [
        'postType' => 'news',
        'args'     => ['public' => true, ...],
        'names'    => ['singular' => 'News', 'plural' => 'News'],
    ],
];
Parameters
$map : array<string, string>

Identifier => absolute file path map from the finder.

extraLines()

AbstractManifestBuilder.php : 259

Extra PHP lines to embed into the manifest after each file's require_once.

protected extraLines(string $identifier, string $file) : array<int, string>

Used primarily for Layotter element class definitions which must exist as named PHP classes at runtime. Most builders return an empty array.

The returned lines are inserted directly into the generated manifest file — they must be valid, complete PHP statements.

Example:

return [
    'class TeaserModule extends \Sloth\Module\LayotterElement { ... }',
    '\Layotter::register_element("teaser-module", "TeaserModule");',
];
